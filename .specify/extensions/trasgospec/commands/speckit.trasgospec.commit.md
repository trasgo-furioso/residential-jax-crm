---
description: Auto-commit and push repository changes with structured messages.
scripts:
  sh: scripts/bash/commit.sh
---

## User Input

```text
$ARGUMENTS
```

## Goal

Perform the full git cycle: detect all changed files repo-wide, use AI judgment to decide what to include, stage selected files, commit with a structured message, and push to the remote. This command is designed to run as an `after_*` hook for every artifact-producing skill, making the commit history the audit log.

## Outline

1. Run `{SCRIPT}` from the repo root and parse the JSON output.

2. **Check for errors**:

   - If `error` is not null (e.g., "Detached HEAD — cannot commit"):
     - Display: "No commit created: {error}"
     - **STOP** — do not attempt any git operations.

   - If `has_changes` is `false`:
     - Display: "No changes to commit."
     - **STOP** — nothing to do.

3. **Inspect changes and decide what to include**:

   For each file in `changed_files`, `new_files`, and `deleted_files`:

   a. **For modified files** (`changed_files`): Run `git diff -- <path>` to inspect the diff. Generate a brief one-liner description of what changed (under 80 chars).

   b. **For new files** (`new_files`): Read the file content (first ~50 lines if large). Generate a brief one-liner description of what the file contains/does (under 80 chars).

   c. **For deleted files** (`deleted_files`): Generate a brief one-liner description like "removed" or context-appropriate description (under 80 chars).

   d. **Flag suspicious files** — ask the user before including:
      - Files that look like secrets: `.env`, `credentials`, `token`, `key`, `secret` in the filename
      - Binary files or large generated artifacts
      - Files that appear unrelated to the current feature/skill context

   e. If all files are straightforward, include everything without asking.

4. **Stage files**:

   Run `git add <file1> <file2> ...` for all files the AI decided to include.

   For deleted files, run `git add <deleted-file>` (stages the deletion).

5. **Commit with structured message**:

   Compose the commit message with one line per file:

   ```
   <repo-relative-path> - <description>
   <repo-relative-path> - <description>
   ```

   **Message format examples** (good):

   ```
   specs/011-audit-and-logs/prd.md - populated problem statement and JTBD
   specs/011-audit-and-logs/spec.md - created feature specification with 4 user stories
   tests/unit/test_commit.py - added unit tests for commit script JSON contract
   bundle/extensions/trasgospec/scripts/bash/commit.sh - implemented git status parser
   ```

   **Message format examples** (bad — do NOT produce these):

   ```
   feat: add audit and logs feature          ← NO tags/prefixes
   Updated spec.md                           ← NO generic descriptions, NO bare filenames
   - specs/011/spec.md - created spec        ← NO leading dashes or bullets
                                             ← NO blank lines between entries
   Co-Authored-By: ...                       ← NO trailers
   ```

   **Message rules**:
   - One line per changed file, no blank lines between entries
   - Each line: `<repo-relative-path> - <description>`
   - Paths are full repo-relative (e.g., `specs/011-audit-and-logs/spec.md`, not `spec.md`)
   - Descriptions are concise (under 80 chars), meaningful, generated by inspecting diffs (for modified files) or file content (for new files)
   - Descriptions focus on *what changed* and *why*, not just "updated" or "modified"
   - No tags, headers, footers, prefixes, bullets, or blank lines
   - No `Co-Authored-By` or other git trailers
   - Use lowercase for descriptions unless referring to proper nouns

   Run: `git commit -m "<message>"`

6. **Push to remote** (if applicable):

   - If `has_remote` is `true`:
     - Run `git push`
     - If push succeeds: display brief confirmation showing which files were committed
     - If push fails: display the error and warn the user, but leave the commit in place

   - If `has_remote` is `false`:
     - Display confirmation of the commit without pushing
     - Suggest: "No remote tracking branch. Run `git push -u origin <branch>` to push."

7. **Display confirmation**:

   Show a brief summary:

   ```
   Committed <N> file(s) on <branch>:
     <path1> - <description>
     <path2> - <description>
   ```

   If pushed: append "Pushed to remote."
   If push failed: append "Warning: push failed — <error>. Commit is saved locally."
